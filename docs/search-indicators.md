# Поисковые индикаторы · необязательный модуль

Модуль временно отключён: `SEARCH_PROVIDER=disabled`. Приведённые ниже действия доступны только при явном `SEARCH_PROVIDER=google_trends`; доступность внешнего источника не гарантируется.

**Автоматически:** администратор открывает `/trends` → **«Настроить автосбор»**. Выбирает время (до двух запусков в сутки по Москве), регион Google (`RU`, `WORLD`, `US`, `RU-MOW`) и историю (год или пять лет), затем включает расписание. **«Обновить автоматически сейчас»** ставит разовый сбор в общую очередь. Собирается весь утверждённый набор фраз; новые фразы добавляются через `/keywords add фраза`. Автосбор общий, не запускается для каждого подписчика. Личные наборы — `/indicators`. По умолчанию шаблон выключен, время 08:30, Россия, пять лет; рабочая настройка этого ПК может быть уже включена по запросу пользователя.

Автосбор использует экспериментальный **неофициальный JSON-интерфейс сайта**, `/trends/api/explore` и `/trends/api/widgetdata/multiline`, без ключей и платных посредников. Сначала выбирается виджет временного ряда, затем загружаются наблюдения. Лимит — 60 HTTP-обращений в сутки, включая ошибки; интервал между запросами не меньше секунды. При 429 сбор оставшихся фраз прекращается и сохраняется пауза не менее часа; после её окончания включённый планировщик автоматически ставит один повтор в очередь, не дожидаясь следующего суточного слота. 401/403, ошибки сети и изменение формата дают безопасную диагностику. Прежние данные и успешные части остаются доступными. Обход CAPTCHA, смена IP для обхода лимитов и отключение TLS не используются. После сна пропущенные слоты объединяются в один свежий запуск; выключение расписания отменяет ещё не начатый автоматический сбор. Включение сбора отдельно от подписок на доставку.

**Резервный импорт CSV:**

1. Администратор открывает `/trends` → **«Загрузить CSV из Google»**.
2. На [Google Trends](https://trends.google.com/trends/explore?geo=RU) выбирает разрешённую фразу, регион и период, тип «Веб-поиск» и категорию «Все категории». Фразы сохраняются из прежнего набора; новые добавляются командой `/keywords add фраза`. Для недельного прогноза нужен хотя бы год истории, для месячного — минимум два года.
3. Скачивает CSV диаграммы **«Динамика популярности»** и отправляет его боту файлом, до 1 МБ. Поддерживаются заголовки День/Неделя/Месяц и Day/Week/Month, UTF-8 с BOM, разделители `,` и `;`. В одном файле до восьми разрешённых фраз; регион берётся из заголовка, числовые ID Яндекса не используются.
4. Проверяет фразы, регионы, период и охват на экране предпросмотра, нажимает **«Подтвердить импорт»**. Подтверждение действует 10 минут; сохраняет данные общий исполнитель, повтор того же файла не создаёт дубликатов.
5. Открывает `/chart trends`: выбирает показатель, период и горизонт → **«Построить график»**. CSV/Excel экспортируются из того же меню. Личный набор фраз и регионов выбирается как отдельные ряды через `/indicators`. Прогнозы, проверка на истории и связи с ЦБ доступны также через рыночную аналитику: `/forecasts market`, `/backtest market`, `/correlations`. Подписка **«Рынок и Google Trends»** использует последнюю успешную загрузку; обновление Google выполняет отдельное расписание автосбора.

Источник: Google Trends. Значения — относительный индекс **0–100**, а не количество поисков. Шкала пересчитывается при каждой выгрузке, включая совместно сравниваемые фразы. Каждая новая выгрузка создаёт отдельную версию ряда, предыдущая сохраняется в архиве; значения не склеиваются. Личные настройки графиков, наборов, пар корреляций и признаков модели следуют за новой версией. Правила уведомлений прежней версии выключаются: их пороги нельзя автоматически переносить на другую шкалу. Архивные версии можно экспортировать по ID через `export_market`; интерфейс графиков использует активную версию. Недельные данные Google подписаны началом недели; для графиков, прогнозов и совмещения с ежедневными рядами используется конец соответствующей недели, чтобы значение не появлялось до окончания периода.

Нули Google могут означать недостаточный объём: `0`, `<1`, пустые значения и незаконченные периоды сохраняются как пропуски с отдельным статусом качества. Пропущенные даты остаются разрывами. Прогнозы считаются локально, обучаются на полном сопоставимом окне, ограничены 0–100; при недостатке истории/охвата или устаревшей дате актуальный прогноз не показывается. Даты публикации в CSV неизвестны, проверки на истории отмечены ретроспективными. Это поисковый интерес, а не подтверждение события.

Новый CSV не закрывает сохранённые прогнозы старой версии фактическими значениями из другой шкалы. Для CSV доступна ретроспективная проверка внутри одной выгрузки; оценка будущего прогноза требует сопоставимых значений источника.

[Официальный Trends API](https://developers.google.com/search/apis/trends) пока требует допуска к alpha. Текущий автосбор не является этим API и может перестать работать при изменениях сайта; резервный путь — [официальная CSV-выгрузка](https://support.google.com/trends/answer/4365538?hl=ru). Если появится одобренный доступ, можно подключить официальный интерфейс с сопоставимой шкалой данных.
