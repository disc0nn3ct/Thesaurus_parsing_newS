# Thesaurus

Сервис для наблюдения за показателями Банка России, RUONIA, Мосбиржей и новостями. Основной интерфейс — бот Telegram: отчёты, подписки и администрирование доступны без браузера. Собирает общие данные, готовит выпуски и доставляет их с учётом личных подписок. История, задания, прогнозы, расход API и состояние каждой отправки хранятся в SQLite. Веб-панель необязательна и по умолчанию отключена. Прежние данные Wordstat сохраняются.

**Как запустить, остановить, обновить бот и сохранить данные:** [пошаговая инструкция](docs/running.md).

## Доллар для поездки

Откройте `/dollar` либо **Рынок и экономика → Доллар для поездки**. Для быстрого анализа
нажмите **«Показать обзор и прогноз»**. Для расчёта своих расходов
выберите **«Моя покупка»**. Настройки сохраняются отдельно для каждого пользователя.

В **«Истории для расчёта»** задайте начало и конец данных: например, с `01.01.2020`
**по сегодня**. «Сегодня» обновляется при каждом расчёте; собственная дата начала
остаётся фиксированной. Есть готовые варианты 1/3/5 лет и вся история. Даты принимаются
как `ГГГГ-ММ-ДД` и `ДД.ММ.ГГГГ`. Явные границы применяются ко всем входным рядам,
дополнительным показателям и проверкам моделей; они имеют приоритет над автоматическим
выбором окна обучения. Недостающие данные не подставляются: отчёт показывает фактически
доступный период. Расчёт использует SQLite без повторной загрузки истории.

Для оценки на конкретный день нажмите **«Курс на дату»**, введите, например,
`15.12.2026` (принимается также `2026-12-15`), затем нажмите **«Построить обзор и прогноз»**.
Дата должна быть после конца выбранной истории, максимум на пять календарных лет вперёд.
Она сохраняется лично для пользователя и не сдвигается автоматически. В результате первым
показан курс на эту дату, метод и диапазон, когда хватает проверочных ошибок. Рассчитывается
одна точка непосредственно на заданный день, без интерполяции месячных прогнозов.
Дальний срок не гарантирует достаточную историю: при отсутствии проверенного улучшения
остаётся базовый ориентир последнего курса, при нехватке ошибок диапазон скрыт.
Прошедшую дату нужно заменить; ввод «Сбросить» возвращает прогноз по числу дней.
Дата прогноза и крайний срок вашей покупки независимы. Смена срока в днях или месяцах
отключает фиксированную дату. Конец истории в прошлом включает ретроспективный расчёт.

Либо выберите **«Срок прогноза»**: 7/14/30/60/90 дней либо своё число 1–90;
для месяцев и лет — 1–60 месяцев. Дневные даты отсчитываются от конца выбранной истории,
месячные — от последнего полного месяца в ней. Это отдельная настройка от даты поездки.
При конце истории в прошлом результат помечается ретроспективным: последующие наблюдения
и известные более поздние публикации исключаются. Текущих рекомендаций о покупке в таком
режиме нет; расчёты сохраняются в отчёте и не попадают в журнал заранее сделанных прогнозов.
Используются имеющиеся версии исторических данных, поэтому это не восстановление всех
исторических публикаций в том виде, в каком они были доступны тогда.

Блок **«Когда рассмотреть покупку»** сравнивает рассчитанные опорные даты, включая выбранные
месячные горизонты. Он показывает аргумент проверить цену сейчас или позже только при
проверке модели на минимум десяти прошлых периодах, улучшении MAE относительно последнего
курса и движении больше типичной ошибки. В «Моей покупке» дополнительно сравниваются
затраты и ошибка в рублях при неизменной наценке банка; даты после срока исключаются.
Базовый прогноз и проценты по рублям сами по себе не превращаются в сигнал снижения курса.
При отсутствии преимущества бот объясняет это, при близком сроке напоминает обеспечить
нужную сумму, при превышении заданного риска предлагает рассмотреть покупку частями.
Опорная дата не является найденным минимумом между расчётами.

Проверка идёт последовательно по прошлым окнам для каждого срока
([метод временной кросс-валидации](https://otexts.com/fpp3/tscv.html)). Для расходов нужна
реальная цена банка: официальный курс и причины его изменения описаны в
[пояснениях Банка России](https://www.cbr.ru/faq/foreign_exchange_market/).

Теперь доступны два режима. **«Обзор рынка»** строит оценку на завтра, через 2, 3 и 7 дней
без срока поездки и банковской цены. **«Моя покупка»** сначала предлагает выбрать крайний
срок кнопками («Сегодня», «Завтра», «Через неделю» или своя дата), затем запрашивает цену
продажи USD банком вам. Неполный персональный запрос не ставится в очередь. Комиссии,
доходность рублей и допустимое удорожание находятся в дополнительных настройках.

На графике ближайших дней серый пустой квадрат — базовый ориентир «последний известный курс»,
оранжевая точка — оценка выбранной модели при достаточной проверке, фиолетовый ромб — уже
опубликованный курс ЦБ. Крестик отмечает сохранение действующего курса по календарю.
Точка показывает результат метода, а не наиболее вероятное точное значение. Полоса строится
как оценка ± 80-й процентиль прошлых абсолютных ошибок при минимум десяти проверках;
она не показывает распределение вероятностей внутри диапазона и не гарантирует будущего попадания.
Опубликованный курс и календарное сохранение не получают модельных диапазонов.

Для анализа на месяцы и годы откройте **«Срок прогноза»**: 1/3/6 месяцев, 1/2/3/5 лет
либо свой срок 1–60 месяцев. Галочка отмечает сохранённый выбор. Затем нажмите
**«Построить обзор и прогноз»**. Срок и метод личные; дата поездки и банковская цена
для этого не нужны. Ближайшие дни остаются в отчёте, дальние ориентиры приходят
отдельным графиком и сохраняются в SQLite вместе с версиями исходных данных.

Дальние модели используют последний доступный курс каждого **полного месяца**
(охват от 90%), а не среднее и не размноженные ежедневные значения. Текущий неполный
месяц остаётся на графике фактов. Отправная точка дальнего расчёта — конец последнего
полного месяца; цели — концы последующих месяцев. «Метод» позволяет сравнивать
последний курс, затухающий логарифмический тренд и прямую ridge-регрессию с лагами
USD 1/3/12 месяцев. «Авто» сравнивает все; окна истории задаются в меню обучения.
Будущие значения макропоказателей не предполагаются: их лаги участвуют в прежней
краткосрочной модели и контексте, а дальние методы используют историю USD.

Для каждого горизонта ошибки вычисляются отдельно, на неперекрывающихся целевых
периодах (до 12 внешних проверок; это не гарантирует их независимость). Настройки
выбираются только внутри прошлого обучающего окна. Сложный метод допускается
при улучшении MAE минимум на 5% и от 10 внешних проверок. Иначе остаётся последнее
значение. Диапазон 80% — эмпирический квантиль абсолютных прошлых ошибок;
при менее 10 проверок показан условный сценарий без диапазона. Линии, уверенно
предсказывающей каждый день следующих пяти лет, нет: график показывает отдельные
проверенные горизонты. Разные валютные режимы и пересмотры данных ограничивают
переносимость результатов всей истории; прежняя ошибка не ограничивает будущую.
В конце дальнего обзора есть исследовательское сравнение числовых вариантов методов
на конечном горизонте. Оно не заменяет выбранный результат: при разном числе
проверок ошибки нельзя напрямую ранжировать.
Если сценарии выключены, на графике серые пустые маркеры обозначают базовый метод «последний курс»;
ромбы дополнительно отмечают нехватку проверок.
Одинаковые значения означают отсутствие подтверждённого направления, а не
предсказание неизменности курса. Оранжевые точки оставлены для сложных моделей,
прошедших проверку; цвет полос совпадает с соответствующим методом.

Кнопка **«Сценарии и частоты истории»** включена по умолчанию и сохраняется лично.
Она добавляет отдельный график медианы и центральных 80% **исторических сценариев**,
а также сглаженные доли роста >2%, изменения в пределах ±2% и снижения >2%
относительно курса последнего полного месяца. Медиана делит сценарии пополам;
она не является «самым вероятным точным курсом». Эти доли предполагают переносимость
прошлой динамики и не гарантируют частоты будущего.

Для каждого срока используются полные неперекрывающиеся интервалы такой же длины;
пропуски не соединяются. Минимум — 10 интервалов; имитация тысяч траекторий не
увеличивает реальную выборку. В авто для сценариев берутся последние 10 лет, если
в них достаточно интервалов, иначе вся история; в каждой прошлой проверке применяется
то же правило. Выбор «после 13.06.2024» не заимствует старую историю. Для долей
применяется сглаживание Dirichlet(1,1,1), исключающее необоснованные 0/100%.

Проверка распределения выполняется последовательно на до 20 неперекрывающихся
будущих относительно обучения периодах. Показаны MAE медианы и последнего курса,
фактическое попадание в сценарный диапазон, Brier для трёх исходов и quantile score
для квантилей 10/50/90%. Статус «исследование» сохраняется при менее 20 исторических
интервалов, менее 10 проверок, Brier не лучше равных шансов, покрытии ниже 65% либо
quantile score не лучше детерминированного последнего курса. Прохождение этих
минимальных критериев не доказывает точную калибровку вероятностей.
Основная модель и её порог улучшения MAE на 5% сохранены. Сценарии, доли, окна,
версии входных данных и проверочные периоды записываются до появления факта;
при его появлении оцениваются сохранённые доли без переобучения.
Методические ориентиры: [распределения прогнозов](https://otexts.com/fpp3/prediction-intervals.html)
и [проверка распределений](https://otexts.com/fpp3/distaccuracy.html).
Расчёт локальный, без повторной загрузки источников. Принцип проверки на прошлом:
[Forecasting: Principles and Practice](https://otexts.com/fpp3/tscv.html).

В начале доставки — краткий вывод и следующий шаг, расходы по дням и ошибка модели в
рублях. Если предполагаемая экономия меньше MAE, бот сообщает, что преимущества ожидания
не видно. Это сравнение при неизменной банковской наценке; фактические изменения спреда
не включены в MAE. Краткосрочные модели проходят внешнюю последовательную проверку:
модель выбирается внутри каждого обучающего окна. Известный опубликованный курс ЦБ на
завтра отмечается отдельно и не попадает в обучение на будущих наблюдениях. Подробные
числа, корреляции и формулы открываются кнопкой; приложены два графика и JSON.

Кнопка обзора или сравнения дней ставит задание в общую очередь и присылает анализ, графики и JSON с расчётами:
динамику USD/RUB, покрытие истории, годовой диапазон и волатильность, доступный экономический
контекст и исследовательские корреляции. Сравниваются затраты на покупку сразу, пополам
и в последний срок при условных изменениях цены на ±5/10%. Это сценарии бюджета, а не
вероятности курса. Фиксированная комиссия учитывается за каждую операцию; ключевая ставка
не используется вместо доходности вклада. При необходимости двойную конвертацию и доступность
наличных проверяйте отдельно у банка.

Прогноз строится локально, без AI и платных API. В **«История обучения и модель прогноза»**
можно выбрать всю загруженную историю, период после 13.06.2024 или автоматическое сравнение
окон (вся история, последние три года, после смены методики). Администратору доступна
**«Дозагрузить всю историю USD и показателей»**: USD загружается с 01.07.1992 через официальный
XML-интерфейс; Brent, ставка США и индекс доллара — с этой даты или фактического начала ряда.
Курс USD до 01.01.1998 делится на 1000 для единого масштаба современных рублей;
это номинальная сопоставимость, не поправка на инфляцию. Данные до июля 1992 в этот ряд не входят.
Исходные сохранённые факты не перезаписываются. Последующие загрузки запрашивают только
недостающие периоды; подтверждённые исторические отсутствия сохраняются как NULL.

Короткие горизонты используют прямую ridge-регрессию логарифмических изменений курса:
свои лаги, признаки известных смен режима, лаги ежедневных ставок, других валют, Brent
и широкого индекса доллара. Отбор по корреляции, стандартизация, заполнение пропусков
признаков медианой, окно и штраф регрессии обучаются только внутри каждого прошлого окна.
Пропуски целевого курса не заполняются и не склеиваются. Более сложная модель публикуется
при улучшении MAE минимум на 5% во внутренней и внешней последовательной проверке;
иначе возвращается последнее значение, с его собственной оценкой ошибки.
В кратком обзоре такой результат прямо подписан как базовый вариант с неопределённым
направлением. Одинаковые значения не означают отсутствия будущих колебаний: рядом показаны
средняя абсолютная ошибка, число проверок и ориентировочный диапазон 80% по прошлым ошибкам.
Десять проверок — небольшая выборка, диапазон не ограничивает возможное движение.
По календарю ЦБ курс, установленный в рабочий день, действует со следующего календарного дня
до следующего курса: прогнозы на субботу, воскресенье и понедельник могут относиться
к одному обновлению. Уже опубликованный будущий курс показан отдельно от модели.
В подробностях доступны причины выбора базового варианта и ошибки кандидата при настройке
и внешней проверке; ошибки настройки не выдаются за итоговую оценку качества.
Месячные и квартальные показатели остаются в контексте, а не превращаются в ежедневные факты.
Неизвестные исторические даты публикации заменяются предполагаемыми консервативными задержками
(Brent 7 дней, ставка США 3, широкий индекс доллара 10, остальные ежедневные ряды 2).
Проверка помечается ретроспективной: эти предположения не восстанавливают исторические версии
и не гарантируют, что пересмотренное значение было известно тогда. В режиме «Вся история»
та же модель отдельно рассчитывает ваш крайний срок покупки; в режиме «Авто» длинные
горизонты используют модели истории USD после смены методики 2024 года.
80% диапазон публикуется при достаточном числе прошлых ошибок. Прогноз,
его входные версии и отчёт сохраняются вместе. Политические новости, розничные котировки банков
и наличие наличных автоматически не загружаются.

**«Обновить все данные для USD»** собирает выбранный набор: USD/EUR/CNY, RUONIA, инфляцию и
ключевую ставку, ликвидность, валютные операции и резервы ЦБ; Brent (EIA), эффективную ставку
федеральных фондов США и широкий индекс доллара (Federal Reserve) через публичные CSV FRED;
экспорт, импорт, торговый баланс, текущий счёт и баланс услуг из текущей квартальной таблицы ЦБ.
Ключи и платные API не нужны. [Инструкция FRED по выгрузкам](https://fred.stlouisfed.org/help/data/downloading/using-the-download-data-link/).
Широкий индекс доллара отличается от DXY; ставка DFF — фактическая эффективная ставка, а не
целевой диапазон ФРС. Даты, единицы и задержки источников сохраняются и показываются.

Состав сбора доступен администратору галочками в **«Источники и свежесть данных»**. Изменение
этого набора не отключает общие источники других проектов. Сбор выполняет общий исполнитель,
не чаще одного запроса в секунду на источник; ошибка отдельного источника даёт частичный результат.
После включения источников они также участвуют в существующем общем автосборе, если он включён.
Повторные обращения запрашивают только недостающие периоды. FRED иногда возвращает полную
CSV-таблицу даже на запрос узкого периода; адаптер фильтрует её по запрошенным датам,
сохранённые значения не перезаписываются. Квартальная публикация проверяется
не чаще раза в день, её годовые итоги исключаются; найденное исправление создаёт инцидент,
старое значение автоматически не заменяется. Текущая таблица ЦБ содержит ограниченную
историю, не является полной исторической выгрузкой платёжного баланса.

Дополнительные данные используются как экономический контекст и, для ежедневных рядов,
как кандидаты признаков короткого прогноза. В отчёте и JSON сохраняются выбранные признаки,
их корреляции на обучении, окно, штраф регрессии, число примеров, ошибки и входные версии
всех источников. Больше источников само по себе не доказывает преимущество ожидания.

Расчёт использует БД и не запрашивает историю заново. Администратор может нажать
«Обновить USD»: включается только ряд `cbr.fx.usd`, используется существующая дозагрузка
недостающих периодов. При отсутствии данных, покрытии ниже 90%, курсе ЦБ старше пяти дней
либо введённой цене банка старше 24 часов текущий совет о покупке приостанавливается.
Итог — объяснение риска срока и бюджета, без обещания самого выгодного курса.

## Установка

Основной проверяемый вариант — Python 3.12 на Windows. Код также поддерживает Linux; для расписаний используется база часовых поясов `tzdata`.

```powershell
cd D:\study\project\Thesaurus_parsing_newS
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В Linux команды выполняются через `.venv/bin/python`. Необязательные TgCrypto и Kaleido вынесены в `requirements-optional.txt`: основной сервис работает без них, а установка TgCrypto может потребовать компилятор.

Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Существующий файл сохраняйте. Заполните локально:

| Переменная | Назначение |
| --- | --- |
| `api_id`, `api_hash`, `bot_token` | Доступ к Telegram через Pyrogram |
| `for_whom_list` | Получатели прежнего однократного запуска, через запятую |

## Запуск

Примеры ниже предполагают активированное окружение `.venv`. Все служебные пути привязаны к проекту, поэтому запускать файл можно из другого каталога.

```powershell
python main.py --dry-run
python main.py status
python main.py
python main.py --section wordstat --recipient 123456789
python main.py serve
```

`python main.py` сохраняет однократный запуск: готовит четыре раздела и отправляет полные выпуски прежним получателям. `serve` поддерживает очередь, расписания и команды Telegram. Для работы сервис должен оставаться запущенным; после сна компьютера пропущенные моменты объединяются в один актуальный запуск на подписку. Одновременно выполняется только один процесс сборки и доставки; блокировка автоматически освобождается при завершении процесса.

`--dry-run` использует только сохранённые данные, создаёт локальные выпуски и не обращается к провайдерам или Telegram. Живую очередь и состояние отправки он не изменяет. `serve --dry-run` выводит состояние расписаний и завершается. Пробную сборку запускайте при остановленном исполнителе: она использует ту же блокировку графиков. `--no-charts` позволяет пропустить построение изображений; `--db путь` выбирает отдельную тестовую базу.

### Сервер без веб-панели

Оставьте `DASHBOARD_ENABLED=0`; пароль панели можно не задавать. `python main.py serve` запускает только Telegram и обработчик очереди: HTTP-порт не открывается, веб-пакеты не импортируются. Графики строятся без графической среды через Matplotlib Agg. Бот получает обновления через исходящее соединение Telegram; входящий порт для webhook не требуется.

На Linux подготовьте окружение в каталоге проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py serve --dry-run
.venv/bin/python main.py serve
```

Для фоновой работы через systemd есть [пример службы](deploy/thesaurus.service.example). В нём используются пользователь `thesaurus` и каталог `/opt/thesaurus`; замените их на свои перед установкой. Пользователю службы нужны права на локальную `.env`, SQLite, артефакты и Telegram-сессию. Файл `.env` читает приложение; секреты в unit-файл не добавляются. Пример принудительно оставляет `DASHBOARD_ENABLED=0` и `AUTO_UPDATE=0`.

```sh
sudo cp deploy/thesaurus.service.example /etc/systemd/system/thesaurus.service
sudo systemctl daemon-reload
sudo systemctl enable --now thesaurus
sudo journalctl -u thesaurus -f
```

На SIGTERM/SIGINT сервис заканчивает текущую операцию, прекращает новые задания и закрывает Telegram-сессию. После принудительной остановки используется обычное восстановление очереди; неоднозначные отправки требуют решения администратора.

### Необязательная веб-панель

Для отдельного запуска установите веб-зависимости, задайте `DASHBOARD_ENABLED=1` и `DASHBOARD_PASSWORD` в `.env`, затем:

```powershell
python -m pip install -r requirements-dashboard.txt
python main.py dashboard
```

Откройте **http://127.0.0.1:8765** и введите пароль. Даже при `DASHBOARD_ENABLED=1` команда `serve` сама панель не запускает. При `0` команда `dashboard` отклоняется до импорта веб-пакетов. Для отключения уже запущенной панели остановите её процесс и верните флаг в `0`; бот продолжит работать отдельно.

Доступ панели ограничен адресом `127.0.0.1`; приложение проверяет Host, Origin, сеанс и CSRF-токен изменяющих запросов. Plotly загружается локально. Панель ставит задания в ту же очередь и не создаёт отдельную Telegram-сессию.

## Проекты в одном боте

`/start`, `/menu` и `/projects` открывают выбор инструмента:

- **Рынок и экономика** → **Построить график**, **Получить отчёт**, **Аналитика и прогнозы**, **Мои настройки и расписания**. Для администратора здесь же **Источники и автосбор**. Прежние команды `/chart`, `/graphs`, `/report`, `/subscriptions` открывают нужный экран напрямую.
- **Жизнь** (`/life`) → **Вино** (`/wines`) → **Моя винотека** (`/cellar`) и **Vivino · карта, отзывы и план** (`/vivino`). Здесь же **Доходы и расходы** (`/expenses`) и **Добавить покупки по чеку** (`/receipt`), если администратор подключил финансовый учёт. Архив из чата Codex не импортируется автоматически: отправьте экспорт в Telegram и подтвердите предпросмотр.
- **Управление сервисом** (`/admin`) → общие пользователи, очередь и лимиты. Источники рынка находятся внутри проекта.

**← Назад** возвращает к родительскому экрану; **⌂ Проекты** — к выбору инструментов. Смена проекта отменяет незавершённый ввод, сохраняя настройки и активные расписания. `/help` объясняет общую навигацию, помощь по рынку доступна внутри его карточки. Telegram показывает общий список быстрых команд; видимость команды не предоставляет права доступа.

Реестр карточек находится в `thesaurus/telegram_projects.py`; маршруты проектов имеют префикс `pj:`. Для нового инструмента зарегистрируйте карточку и обработчики в `ProjectControls`, сохраняя общее меню выбора проектов. Новые личные настройки используют `setting_key(user_id, project_id, name)` и пространство `project:<project_id>:<user_id>:<name>`. Старые ключи рынка сохраняются для совместимости. Один бот обслуживает все проекты; загружаемые архивы не используются как исполняемые модули. Пользовательские вложения исключены из Git.

### Жизнь: доходы, расходы и чеки

Откройте **Жизнь → Доходы и расходы** или `/expenses`. Доход и расход добавляются по шагам: сумма, дата, категория, описание и проверка. Суммы хранятся в копейках. В обзоре доступны итоги, категории, история операций, месячная аналитика и экспорт CSV/Excel. Период выбирается кнопками: текущий месяц, 90 дней, год, вся история или свои даты. Ошибочную ручную запись можно отменить из её карточки; отмена сохраняется в журнале. Разница доходов и расходов относится к записанным операциям, а не к остатку банковского счёта.

**Добавить покупки по чеку** (`/receipt`) принимает PDF до 10 МБ/10 страниц или один JPEG/PNG/WebP до 8 МБ и 12 мегапикселей. PDF с текстом разбирается локально через `pypdf>=6.10` из `requirements.txt`. Для PDF-сканов установите `pypdfium2` из `requirements-optional.txt`; фото и сканы требуют локального OCR: Tesseract с русским языковым пакетом (`rus+eng`) либо Windows OCR с русским языком. Чек не отправляется в облако, платные API и LLM не используются. При отсутствии OCR остаётся ручной ввод. Активное содержимое PDF и вложения не выполняются. Защищённые пользовательским паролем PDF не поддерживаются.

Распознавание выполняется в общей последовательной очереди. Оно создаёт личный черновик на сутки: проверьте итог, дату, оплаченные суммы строк после скидок и количество. Выберите вина галочками; неизвестные производитель и год не выдумываются. Явные обозначения объёма, а также обычные окончания названия вроде `сух.0.75`, распознаются как 750 мл; для объёма без единиц показывается просьба проверить его по бутылке. Неизвестный объём можно подтвердить кнопкой **750 мл для выбранных вин** или указать для каждой позиции. Перед добавлением вин суммы всех строк должны совпадать с итогом чека, а количество бутылок должно быть целым. Нажатие **Сохранить расход и выбранные вина** создаёт одну расходную запись на итог чека и выбранные партии вина в одной транзакции. Повторный импорт того же чека не удваивает расходы или запас. Покупки разных строк сохраняются отдельно, включая различающиеся скидки. Округление цены за бутылку показывается отдельно; расход сохраняется точно по итогу чека.

В карточке товара нажмите **Найти сведения о вине**. Фоновый поиск использует вашу сохранённую загрузку Vivino и открытые карточки подключённых администратором магазинов; сейчас поддерживается Декантер. Магазин получает поисковое название вина и производителя, а не PDF, сумму покупки или фискальные реквизиты. Локальный поиск Vivino не обращается к сайту и не использует загрузки других пользователей; он работает и при недоступности магазина. Учитываются сокращения чеков, варианты написания марок и латинские диакритические знаки. Одно точное совпадение дополняет пустые поля производителя и объёма; при нескольких вариантах или неполном совпадении выберите подходящую карточку. Найденные страна, регион, сорта, описание и ссылка с датой получения сохраняются в примечаниях партии после подтверждения чека. Заполненные вручную поля, количество, дата и оплаченные суммы не заменяются. Год из магазина или прежнего отзыва Vivino не переносится на неизвестную бутылку: отдельная кнопка **Год на моей бутылке: … · подтвердить** позволяет подтвердить его по этикетке. Исправление названия, производителя, года или объёма убирает автоматически заполненные данные прежнего вина; устаревший результат нельзя применить к изменённой карточке. При изменении названия объём и год из текста определяются заново, ручные уточнения сохраняются. Повторное дополнение обновляет сведения источника без дублирования примечаний. Повторный поиск использует кэш на 30 минут; замена загрузки Vivino меняет ключ кэша. Сетевые ошибки оставляют ручной ввод доступным. Для этого нужны оба права: `life_finance` и `wine_cellar`; новые магазины подключает только администратор.

В карточке товара показаны изменения **было → стало**: название, производитель, год, объём, страна, регион, сорта и исправления количества или оплаченной суммы. В проверке чека кнопка **Изменения: было → стало** открывает сравнение по товарам, а кнопки товаров показывают итоговые названия. При однозначном совпадении или выборе найденной карточки её название становится названием вина; ручное название имеет приоритет. В запасы при подтверждении попадают итоговые значения выбранных вин. Исходная строка сохраняется отдельно для сравнения, включая после перезапуска; название в уже учтённом чеке не переписывается.

Чек, открытый из винотеки, после сохранения возвращает в винотеку. Если расход уже записан без бутылок, откройте **Добавить вино → Учтённые чеки · добавить вина** либо карточку расхода → **Добавить вина из этого чека**. Проверьте сведения и подтвердите выбранные позиции. Этот режим добавляет только ещё не внесённые строки чека, сохраняет дату, количество и оплаченные суммы и не создаёт второй расход. Повторное подтверждение не удваивает запас. Обычный повторный импорт чека по-прежнему ничего не добавляет без такого явного выбора.

Право **Жизнь · доходы, расходы и распознавание чеков** (`life_finance`, раздел `life`) выдаёт администратор через карточку пользователя. Оно не открывает винотеку: для добавления бутылок нужно также `wine_cellar`. Прежние права на вина (`vivino`) сохраняются; они открывают **Жизнь → Вино**, без автоматического доступа к финансам. Команды, загрузка, очередь, подтверждение и каждая часть доставки повторно проверяют права. Пользователь изменяет только свой учёт. Локальные файлы чеков находятся в `data/receipts/<Telegram ID>/`; БД хранит разобранные товары и хеш идентификатора, без исходных фискальных номеров и полного OCR-текста. Миграция создаёт резервную копию `*.life-backup-*.sqlite3` и выполняется транзакционно.

В меню ввода остаётся одна **Отмена**, отдельный **Назад** возвращает в контекст, а **Проекты** открывает главное меню. Выбор галочек редактирует текущее сообщение. Список пользователей запрашивает недостающие имена у Telegram и показывает имя, `@username`, ID, права и `/start`; если имя недоступно, это указано явно. **Обновить имена** проверяет до шести пользователей текущей страницы за один раз.

### Вина: личная винотека

Откройте **Жизнь → Вино → Моя винотека** или `/cellar`. **Добавить вино** открывает выбор способа: **Ввести вручную**, **По фото этикетки**, **По чеку · PDF или фото**. Чек виден при подключённом финансовом учёте. Отдельная кнопка **Пример ручного ввода** показывает все восемь полей и формат ответов. Вручную бот спрашивает по одному полю: название, производитель, год урожая, число бутылок, объём одной бутылки, цена за бутылку в рублях, дата покупки и место хранения. На каждом шаге есть пример. Отправляйте только значение текущего поля отдельным сообщением: например `Merlot Reserva`, затем `Bodega Ejemplo`, `2021`, `2`, `750`, `1250,50`, `01.10.2025`, `Шкаф, полка 2`. Объём 0,75 л вводится как 750 мл; для двух бутылок по 1250,50 ₽ укажите цену 1250,50, а не общую сумму. Неизвестные производителя, год, цену, дату и хранение можно пропустить кнопкой. Запись появляется только после подтверждения; перед ним поля можно исправить. Для покупки того же вина по другой цене добавьте новую партию.

В карточке вина доступны **Выпил одну бутылку**, **Добавить бутылки**, **Указать цену и дату**, ссылка на товар и обновление цены. Списание требует подтверждения и не допускает отрицательного остатка; повторное нажатие не списывает бутылку ещё раз. При добавлении бутылок к существующей партии используется её прежняя цена покупки. Цена покупки и последующие оценки хранятся отдельно.

**По фото этикетки** принимает фотографию для локального чтения названия и года. Бот предлагает черновик, который нужно проверить: распознавание не подтверждает производителя, год урожая или объём без вашего участия и не добавляет запас автоматически. На Windows используется встроенный Windows OCR, если доступен языковой пакет распознавания; дополнительных обязательных Python-зависимостей нет. На Linux и Raspberry Pi можно установить Tesseract с нужными языковыми данными и добавить исполняемый файл `tesseract` в `PATH`. `WINE_OCR_LANG=eng` задаёт язык Tesseract; несколько установленных языков указываются через `+`. Если локальное OCR недоступно или не прочитало этикетку, остаётся ручной ввод.

При необходимости можно подключить уже установленную локальную модель Ollama с поддержкой изображений: задайте `WINE_VISION_MODEL` (совместимый прежний ключ — `OLLAMA_VISION_MODEL`) и локальный `OLLAMA_URL`. Обычная текстовая `OLLAMA_MODEL` не заменяет модель зрения. Модели автоматически не скачиваются, облачные модели не используются, фото не отправляются во внешние API. Порядок попыток: Tesseract, Windows OCR, настроенная Ollama; первый читаемый результат всё равно требует проверки. Доступность OCR и модели зависит от сервера.

**Стоимость и динамика** показывает число бутылок, известные затраты на оставшийся запас, последнюю сохранённую оценку и разницу с ценой покупки. Если часть цен неизвестна, показывается стоимость известной части и её охват; полная стоимость остаётся неизвестной. Покупки и выпитые бутылки меняют состав коллекции, поэтому изменение общей суммы не считается доходностью: изменение цен для тех же бутылок учитывается отдельно от пополнений и списаний. История создаётся при операциях с запасами и ценами. Это история ваших сохранённых оценок, а не восстановленная история магазинных цен до подключения.

Отдельно показано **Изменение оценки по ценам магазинов**: сумма `(последняя цена магазина − цена покупки) × оставшееся количество` только по позициям, у которых известны обе цены и сохранён адрес источника. Рядом указаны охват и даты магазинных цен. Одна лишь цена покупки не считается новой ценой магазина. Эта разница не записывается как полученный доход в финансовый учёт; кнопка **Добавить доход** доступна в самостоятельном разделе **Жизнь → Доходы и расходы**.

**Таблица и экспорт** предоставляет CSV, Excel, HTML и график стоимости. В таблицах есть вино, производитель, год, остаток, объём, цена покупки, последняя оценка, её дата и источник. Неизвестные значения остаются пустыми; текст защищён от выполнения формул при открытии таблицы.

Винотека привязана к числовому Telegram ID. Подписчик видит и изменяет только собственные запасы. Администратор может открыть **Винотеки пользователей · просмотр**, но не изменять чужие бутылки или цены. Новое право `wine_cellar` выдаётся через **Управление сервисом → Пользователи → карточка → Отдельные функции → Вина · моя винотека, запасы и стоимость**. Прежний доступ к Vivino не подключает винотеку существующим подписчикам автоматически; администратор выдаёт его отдельно. Администраторы имеют доступ ко всем функциям.

### Вина: обновление цен магазинов

Администратор открывает **Вина → Магазины · Москва** и подключает источники галочками. Настройки общие; подписчик не может подключать магазины самостоятельно. Само включение источника не означает успешную проверку цены: отдельно показаны возможности интеграции и состояние последнего запроса. По умолчанию новые профили выключены; Москва — единственный поддержанный город розничного сравнения.

В карточке своей бутылки выберите **Цены в Москве → Найти это вино в магазинах**. Задание выполняется общим исполнителем и присылает результат в Telegram. У «Декантера» поддержаны публичный поиск и проверка конкретной карточки: открываются первые три настоящих результата, рекомендации не учитываются. Найденную бутылку нужно проверить по названию, производителю, году урожая и объёму и подтвердить. Только после подтверждения сохраняются ссылка и оценка; запас не меняется. Результат действует 30 минут, повторное нажатие во время выполнения не создаёт второе задание. Отключение магазина или отзыв личных прав блокирует подтверждение уже найденной цены.

У «Ароматного мира» поддержана проверка **сохранённой точной ссылки** в выбранном московском магазине; автоматический поиск не подключён. Если магазин не публикует год урожая, бот не угадывает его и не включает цену в оценку конкретного винтажа. Для «ВинЛаба», «Перекрёстка» и SimpleWine показан ручной режим: при проверке публичные страницы потребовали взаимодействия с сайтом либо вернули защиту/отказ. Обход защиты, вход в аккаунты и скрытые API не используются. Цену покупки или оценку с датой можно указать вручную.

Кнопка **Обновить цены по моим ссылкам** повторно проверяет сохранённые карточки. В **Стоимости и динамике** можно обновить все ссылки винотеки. Используется положительная публичная RUB-цена и подтверждённое наличие; зачёркнутые, клубные, персональные, цены «от» и нулевые значения не подходят. При нескольких подходящих предложениях выбирается минимум. Проверенная московская цена не смешивается с более дешёвыми предложениями неизвестного региона. Ошибка отдельного магазина сохраняет остальные результаты и прежнюю оценку проблемной бутылки. При проверке видны город, место наличия, дата и ссылка. **Это розничная стоимость замены бутылки, не гарантированная цена продажи вашей коллекции**; доставка и скидки по картам не учитываются.

В **Магазины · Москва → Разрешённые домены · дополнительно** остаётся настройка собственных источников через `schema.org Product/Offer`. При отсутствии настройки в БД используется `WINE_PRICE_ALLOWED_HOSTS` из `.env`; **сброс** возвращает этот список. Подключённые готовые профили добавляются к нему. Отключение профиля удаляет соответствующий домен из разрешённых, сохраняя другие пользовательские домены. Пустой список при выключенных профилях запрещает сетевые обращения. Домен и вариант с `www` считаются одним магазином; другие поддомены разрешаются отдельно. Проверки кэшируются 30 минут с сохранением исходной даты наблюдения; запросы ограничены одним в секунду к магазину. Все обращения используют проверенные публичные DNS-адреса, ограничены по времени и размеру; перенаправления проверяются повторно. `--dry-run` не обращается к магазинам.

### Вина: сверка с отзывами Vivino

После подтверждённого импорта Vivino новый личный отзыв или оценка может создать предложение в **Моей винотеке → Предложения по отзывам Vivino**. Сопоставление использует название, производителя и год. Первоначальный набор и уже загруженная до обновления история становятся исходной базой и не приводят к предложениям списать старые дегустации. Повторный импорт и редактирование того же отзыва не создают нового списания.

Бутылки не списываются автоматически. Откройте предложение, выберите конкретную партию, если их несколько, и подтвердите списание одной бутылки. Если вино пробовали в ресторане или из чужих запасов, выберите **Не списывать**. Удаление набора Vivino не удаляет запасы винотеки и их стоимость.

### Vivino: загрузка и карта

1. Откройте `/vivino` → **Загрузить ZIP / CSV**.
2. Отправьте ZIP до 10 МБ с единственным `full_wine_list.csv` (вложенная папка допустима) либо сам CSV в UTF-8 до 8 МБ. До 3000 записей; RAR перепакуйте в ZIP. Прочие файлы экспорта, профиль, устройства, изображения и координаты сканирований не сохраняются. ZIP не распаковывается на диск; проверяются пути, ссылки, объём и структура CSV.
3. Проверьте число записей, отзывов, дубликатов и некорректных оценок → **Сохранить и построить карту**. Предпросмотр действует 10 минут, до подтверждения прежний набор сохраняется. Импорт заменяет только ваш набор Vivino.
4. Общий последовательный исполнитель строит **географический HTML-атлас** и отправляет файл в личный чат. Скачайте его и откройте браузером. Файл работает без интернета и внешних библиотек: тепловая заливка стран, масштабирование, разделы регионов, сортов и своих вин, поиск, фильтры страны, сорта и прогресса, карточки с описаниями, оценками и отзывами. Нажатие на страну открывает её вина и подтверждённые сорта; выбор сорта показывает страны содержащих его вин.

**Заливка стран:** число разных подтверждённых вин одной винодельни, года, страны и региона; повторные сканирования одного вина не увеличивают счёт. Ноль — нейтральный цвет, больше вин — темнее бордовый. Шкала фиксируется относительно максимума всей личной коллекции и не меняется при фильтрации; насыщенность использует квадратный корень отношения к максимуму, чтобы малые значения оставались видимыми. Заливка реагирует на фильтры. Неподтверждённые дегустации и неизвестная страна не добавляют интенсивности; ручная отметка сорта или региона без конкретного вина тоже не увеличивает счёт страны. Точные точки регионов выключены по умолчанию и включаются отдельно.

**Аналитика и что попробовать** доступна в HTML и кнопкой в меню Vivino. По каждому подтверждённому сорту показаны число разных вин, число оценённых вин, средняя личная оценка, купажи и страны фактических вин. Повторные записи одного вина объединяются; его разные личные оценки усредняются, одинаковые повторные оценки учитываются один раз. Средняя оценка сорта — оценка содержащих его вин, а не самого сорта. Сравнение предпочтений появляется при трёх оценённых разных винах на сорт. При неизвестном или неполном составе показан охват и предлагается уточнить сорта.

Предложения сначала показывают незавершённые личные цели, затем вина из собственного экспорта без подтверждённой дегустации с ещё не отмеченными сортами; при достаточных оценках учитывают присутствие уже высоко оценённых сортов в составе. Далее предлагаются до трёх неотмеченных стартовых сортов из фиксированного набора: Cabernet Sauvignon, Chardonnay, Pinot noir, Merlot, Riesling, Syrah, Sauvignon blanc, Tempranillo. Это явно обозначенные цели для знакомства, а не персональный прогноз вкуса; при неизвестном составе есть предупреждение, что сорт мог уже быть попробован. Для расширения географии добавляются неотмеченные регионы, по одному на страну, начиная с меньшего числа попробованных вин. Это прозрачные исследовательские цели, без прогнозирования вкуса, рекомендаций конкретного магазина или проверки доступности вина. Происхождение сорта из справочника не используется для догадок о месте выращивания конкретного вина.

**Регионы и план** и **Сорта и план** доступны в боте даже до импорта. Фильтры **Все**, **Пробовал**, **Не отмечено**, **В плане** показывают личный прогресс. Откройте карточку → добавьте цель в план или отметьте дегустацию. Поиск принимает название или его известный синоним. Если цели нет в справочнике, нажмите **Добавить свою цель**: регион вводится как `название; страна; широта; долгота; описание` (обе координаты можно оставить пустыми), сорт — `название; описание`. Координаты WGS84: широта от −90 до 90, долгота от −180 до 180. Собственные цели видны только в вашем наборе и администратору при просмотре этого набора.

**Мои вина и сорта** → карточка вина позволяет изменить отметку «пробовал» и указать сорта через точку с запятой. По умолчанию вино считается попробованным, если в экспорте есть личная оценка или отзыв; одно сканирование этикетки этого не подтверждает. Регион и сорт отмечаются по попробованным винам либо явно пользователем. Состав сортов берётся из колонок `Grapes` / `Grape varieties` или ручного ввода; название вина и стиль не используются для догадок. Отсутствующий состав показывается как неизвестный. Пропущенные оценки не превращаются в ноль.

Справочник содержит снимок 777 регионов и 1637 сортов с идентификаторами VIVC из Wikidata; это **не полный перечень всех виноградных регионов и винных сортов мира**. Регион без точной координаты остаётся в списке; его вино увеличивает заливку страны, если страна известна. Координата региона не обозначает место винодельни, происхождение сорта не означает страну конкретного вина. Описания и ссылки ведут к исходным записям; их полнота и язык зависят от источника. Методика и лицензии — в [описании справочников](thesaurus/resources/README.md). Тексты CSV вставляются как текст, активный HTML не выполняется; карта и аналитика не обращаются к API или LLM.

План, уточнения сортов и отметки сохраняются отдельно для числового Telegram ID и сохраняются при повторном импорте. HTML — снимок: после изменений нажмите **Географическая карта** для нового файла. Администратору доступна кнопка **Пользователи Vivino**: список загрузивших данные с пагинацией, карточка пользователя, его регионы, сорта, вина и запрос карты. Просмотр чужого набора не позволяет менять его отметки или план; карта отправляется запросившему администратору. Подписчик видит только собственный набор. Все действия проверяют права и личный чат; добавление пользователя не повышает его права.

Повторные нажатия не создают копии задания; после сбоя подтверждённые части доставки не отправляются повторно. Результат доступен в `/history`. Личный набор и предпросмотр хранятся в SQLite, файлы — рядом с базой в `vivino/<Telegram ID>/`. **Удалить мои данные** стирает набор, предпросмотр, личный план, отметки, уточнения и локальные HTML, включая копии, построенные для администратора; отменяет ожидающее построение и доставку. Уже отправленные сообщения, скачанные копии и резервные копии базы удаляются отдельно. Смена набора, отзыв доступа или удаление данных блокируют последующие части доставки старой карты. Настройки рынка сохраняются.

## Подписки и управление

Каждому разрешённому пользователю доступны собственные разделы, фразы из утверждённого списка, регионы, часовой пояс, дни недели и подробность. По умолчанию используется краткий выпуск с кнопкой «Подробнее». Управление принимается только в личном чате после проверки числового Telegram ID, включая нажатия кнопок.

Начальные шаблоны **выключены**:

| Раздел | Время Europe/Moscow | Дни |
| --- | --- | --- |
| AI | 08:30, 18:30 | Каждый день |
| RUONIA | 15:30 | Каждый день |
| Регионы | 10:00 | Каждый день |
| Wordstat | 09:00 | Среда |

Примеры команд:

```text
/help
/status
/report wordstat brief
/subscriptions
/subscriptions ai on 08:30,18:30
/subscriptions wordstat detail full
/subscriptions wordstat weekdays 2
/subscriptions ai timezone Europe/Moscow
/keywords
/keywords set wordstat обвал|рост цен
/regions
/regions set 213,2
```

У подписчика `/regions set` меняет личный выбор; у администратора — общий состав регионов. Для личного выбора администратора используется `/regions mine`. Администратор разрешает и отзывает доступ через `/allow ID`, `/deny ID`, меняет список фраз через `/keywords add фраза|тема` и `/keywords remove фраза`. Кнопки «История» и «Данные и прогнозы» открывают сохранённые выпуски и аналитику; «Управление сервисом» показывается только администраторам.

Основные действия без веб-панели:

| Команда | Действие |
| --- | --- |
| `/history [раздел]` | Свои выпуски и кнопки открытия подробностей |
| `/export wordstat csv 2026-09-01 2026-09-30` | CSV по собственным фильтрам; вместо `csv` можно `xlsx` |
| `/forecasts` | Сохранённые прогнозы и оценка точности по выбранным запросам |
| `/backtest` | Проверка на истории через общую очередь, с результатом в Telegram |
| `/admin` | Меню администратора |
| `/users` | Разрешённые пользователи и роли |
| `/jobs failed` | Ошибки заданий; доступны также `pending`, `running`, `done` |
| `/budget` | Лимиты, токены, тарифы и расходы за московский день |
| `/budget ai 8` | Изменить дневной лимит AI; аналогично `wordstat` и `ai_tokens` |
| `/budget price ai output_per_million 0.5` | Задать тариф; это пример синтаксиса, не цена провайдера |
| `/alerts` | Правила аномалий, кнопки включения и инструкции изменения порогов |
| `/proposals` | Предложения фраз AI с кнопками принятия и отклонения |
| `/proposals request` | Поставить создание предложений в очередь; расходует бюджет AI |
| `/verify ID_выпуска` | Администратор ставит проверку доступности источников в очередь |

Экспорт и проверка прогнозов выполняются последовательно общим исполнителем, а файлы приходят через обычную возобновляемую доставку. Команды обработчика Telegram сами платные API не вызывают. Доступ повторно проверяется перед исполнением заданий; история других подписчиков не открывается обычному пользователю. Время доставки, набор разделов и подробность меняются через `/subscriptions`.

## Данные и качество

Пустой ответ ЦБ за конкретные даты отличается от ошибки парсера: принимается только официальный ответ «За выбранный вами период нет информации» с формой периода либо таблица с полностью совпавшими заголовками. У многотабличных наборов, например месячного MIACR, пустая таблица не мешает сохранить остальные. Изменение заголовков, колонок или числового формата остаётся ошибкой с понятной причиной.

Подтверждённые отсутствующие периоды старше 30 дней запоминаются отдельно от значений. Они остаются пропусками, не становятся нулями и не запрашиваются каждый час. Недавние отсутствующие публикации повторно проверяются после паузы. Полную историю можно перепроверить через «Целостность данных». Существующие значения при обычном обновлении не перезаписываются.

Если источник возвращает разные значения одного показателя на одну дату, спорное новое наблюдение изолируется как пропуск, а все варианты записываются в журнал `/integrity`. Однозначные остальные даты сохраняются. Набор остаётся частичным с понятным предупреждением; усреднение или выбор последней строки автоматически не выполняются.

В обзоре ставки меняются в процентных пунктах; указана дата предыдущего наблюдения. Покрытие относится к явно указанному диапазону сохранённой истории, а не к свежести сегодняшней публикации. Данные вне расчётного календаря отмечаются отдельно и не повышают покрытие. Волатильность не соединяет значения через пропуски. Корреляции и ошибки источников выводятся обычным текстом, машинные показатели сохраняются в SQLite.

Для диагностики всех подключённых наборов ЦБ без изменения базы и рассылки:

```powershell
.\.venv\Scripts\python.exe scripts\audit_cbr_sources.py --output data\diagnostics\cbr-audit.json
```

Это проверка официальных ответов за последние 32 дня (для месячных/квартальных рядов начало выравнивается по периоду; для архивов используется конец доступной истории). Она выполняет реальные бесплатные запросы последовательно, максимум один в секунду. Проверка не подтверждает полноту всей истории. Результат последнего обследования: [диагностика ЦБ 09.10.2026](docs/cbr_diagnostics_2026-10-09.md).

- Начальный постоянный список содержит восемь резервных фраз с тематическими группами. AI может предложить дополнения; применение требует действия администратора. Каждая редакция списка сохраняется отдельно.
- Первая региональная загрузка закрепляет до 25 регионов с наибольшей суммой запросов «пожар», «взрыв» и «бпла». При неполном исходном ответе состав не утверждается. Изменение состава создаёт новую версию и отмечается при сравнении выпусков.
- Наблюдение уникально по источнику, показателю, региону, устройствам, частоте и дате. Wordstat догружает новые периоды и перепроверяет последние четыре недели либо семь дней. Недельные значения хранятся с датой закрывающего воскресенья. RUONIA использует SQLite и запрашивает у ЦБ только недостающие даты; сохранённая история повторно не скачивается.
- Существующий `ruonia_data.xlsx` импортируется один раз. Исходный Excel, старые результаты и пользовательские медиафайлы сохраняются без изменений.
- В выпусках и панели показаны даты данных и загрузки, ожидаемые/фактические наблюдения, пропуски, полнота и использование кеша. Для RUONIA полнота учитывает российские рабочие дни. Пропуск не подменяется нулём.
- Получатели используют общий сбор данных и AI-обзор. Кеш учитывает день и версии настроек; успешный RUONIA обновляется не чаще раза в 30 минут, региональные данные — раза в час. AI имеет утренний и вечерний выпуски, Wordstat кешируется на день. Частичный результат содержит причину ошибки и допускает повтор через пять минут; при сбое AI сохраняется предыдущий обзор с его исходной датой.
- Изменения чисел сравниваются с последней завершённой доставкой получателю. Новости сопоставляются по нормализованным ссылкам и заголовкам; повторы сворачиваются, уточнения выделяются отдельно.

Начальное правило аномалий требует изменения недельной суммы минимум на 50%, отклонения минимум на 2,5 стандартного отклонения от восьми предыдущих недель, покрытия не ниже 90% и среднего базового объёма не меньше 20 запросов. При недостаточной истории сигнал не создаётся. Для одной пары «правило/фраза/регион» действует интервал не менее 24 часов. Поисковый интерес не равен числу происшествий.

Структурированные утверждения AI сохраняются вместе со ссылками, датами и результатами числовой сверки с RUONIA/Wordstat. Наличие доступной страницы не подтверждает утверждение. Проверка доступности источников выполняется отдельным заданием по действию администратора, с ограничением разрешённых доменов и без доступа к локальным сетевым адресам.

## Прогнозы, бюджеты и доставка

### Прогнозы RUONIA и работа без Perplexity

`/report ruonia full` строит локальные прогнозы для ставки RUONIA, накопленного индекса, срочных ставок на 1/3/6 месяцев и объёма сделок. Ставка и объём загружаются через публичную службу Банка России; индекс хранится отдельно от ставки. Объём измеряется в млрд рублей, индекс — в единицах индекса, ставки — в процентах. Прежние ошибочно подписанные наблюдения индекса переносятся под правильное название транзакционно, после резервной копии SQLite; старые выпуски остаются историческими снимками.

**Меню Telegram:** сервис сам регистрирует список команд и стандартную кнопку меню рядом с полем ввода ([официальный интерфейс Telegram](https://core.telegram.org/api/bots/menu)). При `/start` показывается главное меню и обновляется личный список команд; команды администратора видны только в его списке. Проверки доступа действуют независимо от видимости команд. Если Telegram показывает прежний экран, отправьте `/start` и заново откройте чат.

**График каждую пятницу:** `/chart ruonia` → «Показатель» → `RUONIA` → выберите период (например, 3 месяца) и прогноз (например, 4 недели) → «Отправлять по расписанию». В новом расписании уже выбрана пятница и 15:30 по Москве. Настройте время, нажмите «Сохранить текущий график» и «Включить отправку». Расписание сохраняет собственный снимок настроек: последующие разовые графики не меняют его. Для изменения вернитесь на экран графика, выберите параметры и снова сохраните их в расписание. Раздел `/graphs` и «Мои настройки → Графики по расписанию» открывают все ваши расписания; отчётные подписки настраиваются отдельно.

Регулярный график показывает выбранный скользящий период до дня отправки; известные пропуски остаются разрывами. Прогноз обучается на всей доступной истории и показывается при достаточной свежести/полноте. Фиксированные даты предназначены для разовых графиков. Для RUONIA по умолчанию перед отправкой догружаются только недостающие данные; кнопка «Использовать только базу» отключает эту загрузку. Поисковые графики недоступны при `SEARCH_PROVIDER=disabled`. После сна сервера расписание объединяет пропущенные запуски в один актуальный график. Выключение отменяет ожидающие задания и ещё не отправленные части; подтверждённые сообщения не отправляются повторно. Данные и настройки сохраняются после перезапуска.

**Уведомления по параметрам:** выберите один показатель в графике → «Уведомления по показателю» → «Настроить уведомление». Выберите условие (выше/ниже значения, изменение в процентах, отклонение в σ или пересечение порога), порог, размер окна, минимальный охват (90–100%) и интервал повторов (1–720 часов). Затем включите немедленную доставку или сводку. Новые правила выключены, изменение условия также выключает правило до повторного включения. Сохранённая RUONIA доступна для уведомлений без включения внешнего рыночного источника; её личные фильтры сохраняются. Проверка выполняется при очередном обновлении данных. `/notifications` открывает все личные правила.

Обновление сначала читает свою SQLite-базу. Запросы к ЦБ охватывают только новые даты и пробелы внутри истории, включая значения `NULL`. Сохранённые числа и исходное время их загрузки не перезаписываются. Индекс и срочные версии учитывают календарные дни, ставка и объём — российские рабочие дни. Обычный отчёт RUONIA и рыночный сбор используют общую сохранённую историю всех шести показателей; SOAP возвращает ставку и объём вместе, повторно для второго показателя запрос не выполняется. Перезапуск сервиса и истечение кэша отчёта не приводят к повторной загрузке истории. Подтверждённый пустой ответ означает отсутствие публикации: повтор для этих дат возможен через час; сетевые ошибки не помечают даты загруженными. Первоначальная история или её расширение загружаются только в недостающей части. Уже сохранённые периоды автоматически на исправления не перепроверяются.

На экране графика срок прогноза задаётся отдельно: до 24 месяцев. Для ставки и объёма используется рабочий календарь РФ, для индекса и срочных ставок — календарные дни. Нужны минимум 60 фактических ежедневных наблюдений и 90% покрытия сопоставимого ряда. Последнее значение, затухающий тренд и ridge сравниваются последовательной проверкой на истории. Диапазон 80% публикуется только при наличии минимум десяти прошлых ошибок для соответствующего горизонта. Изменения политики ЦБ она предсказывать не умеет. Прогнозы сохраняются до факта; ошибки считаются отдельно по показателям, чтобы не смешивать проценты, индекс и объём. Пропуски не заменяются нулями.

```text
/report ruonia full
/forecasts ruonia
/backtest ruonia 12
/export ruonia xlsx
/keywords set ruonia RUONIA|1 мес|3 мес|6 мес
```

Проверка из терминала: `python main.py backtest --section ruonia --output data/ruonia-backtest.json`. Проверка на истории использует только данные до каждой точки обучения; пересмотренные исторические значения могут отличаться от доступных тогда.

Выбор текстового движка в `.env`:

| `AI_BACKEND` | Поведение |
| --- | --- |
| `template` | Обзор сохранённых чисел по шаблону, без модели, ключей и платных запросов |
| `ollama` | Комментарий локальной модели; при недоступности — шаблон, без обращения к облачному AI |
| `perplexity` | Прежний адаптер с поиском и дневным бюджетом API |

В `.env.example` выбран `template`. Если переменная отсутствует в старой конфигурации, для совместимости используется прежний адаптер. Для перехода добавьте `AI_BACKEND=template` либо `AI_BACKEND=ollama` и перезапустите `serve`. Команда `/report ai brief` в бесплатных режимах объясняет уже загруженные данные: сначала запросите RUONIA или Wordstat. Это не поиск свежих новостей. Выводы локальной модели не считаются подтверждёнными; числовые прогнозы рассчитывает отдельная модель рядов.

Для Raspberry Pi 5 8 ГБ стартовый вариант — [Qwen3 1.7B в Ollama](https://ollama.com/library/qwen3:1.7b), квантование Q4_K_M, файл около 1,4 ГБ. Это оценка пригодности по размеру модели, не замер скорости на Raspberry Pi. Установите Ollama по [официальной инструкции Linux](https://docs.ollama.com/linux), затем:

```sh
ollama pull qwen3:1.7b
```

В `.env`:

```dotenv
AI_BACKEND=ollama
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:1.7b
```

Ollama должен работать на том же компьютере. Приложение допускает только локальный HTTP-адрес, запрещает перенаправления, использует 4 потока, контекст 2048 и максимум 384 выходных токена, отключает режим размышлений и выгружает модель после ответа. Ответ может занимать заметное время. Само вычисление использует токены модели, но счёта за них нет; дневной бюджет платного AI не расходуется. Предложения новых фраз через `/proposals request` работают с Ollama и по-прежнему требуют утверждения администратора; шаблонный режим их не генерирует.

Прогнозы на 1–4 недели сохраняются до появления фактических значений. Модель работает с недельными рядами в `log1p`; для контроля используется прогноз «как на прошлой неделе». Последовательная проверка на истории обучается только на предшествующих данных и показывает MAE, WAPE и покрытие диапазона. Ретроспективная проверка отделена от оценки действительно сохранённых прогнозов; диапазон приблизительный.

```powershell
python main.py backtest --phrase "рост цен" --output data/backtest.json
```

Начальные дневные бюджеты: **300 попыток Wordstat**, **8 попыток AI**, до **2200 выходных токенов на AI-запрос**. Дневная граница — полночь Москвы. Каждая попытка, в том числе повтор после ошибки, резервируется до запроса. По исчерпании лимита сохраняется частичный результат. Денежная оценка появляется только после задания тарифов администратором; без тарифа показываются обращения и токены.

У каждой части доставки есть состояние и ID подтверждённого Telegram-сообщения. Подтверждённые части не отправляются снова. Таймаут или прерывание между отправкой и записью результата создаёт состояние `uncertain`; автоматического повтора нет. Администратор сверяет чат и выбирает действие в панели либо:

```text
/resolve ID retry
/resolve ID sent
```

Ошибка одного получателя не останавливает доставку остальным. Отключённому пользователю новые части не отправляются.


Новые источники выключены. В личном чате откройте `/admin` → «Источники рынка»,
включите нужные группы и запросите `/market`. Первый сбор загружает историю,
последующие — только новые периоды и пробелы, с повторным использованием SQLite. Расписание включается отдельно:
`/subscriptions market on 18:30`; формат — `/subscriptions market detail brief|full`.
Панель и платные AI для этого не нужны; `AI_BACKEND=template` сохраняет полностью бесплатный режим.
Общее обновление источников настраивается независимо от доставки:
В боте: `/admin` → **«Автосбор данных»** (или `/autocollect`). Здесь включается и выключается автосбор **ЦБ/Мосбиржи**, видны текущее состояние и время по Москве. Кнопки настроек открывают выбор времени и параметров источника. При `SEARCH_PROVIDER=disabled` поисковые источники скрыты и не могут быть включены через старые кнопки. Выключение сохраняет настройки и отменяет ожидающие автоматические задания этого источника; уже начатый сбор завершается. Разовые ручные обновления остаются доступны. Повторное включение запускает расписание с текущего времени, без сбора пропущенных за время отключения запусков. Личная доставка отчётов включается отдельно через `/subscriptions`. Эти общие переключатели доступны только администратору в личном чате.

Из команд:
`/sources schedule on 10:00,18:30`; выключение — `/sources schedule off`.
Ручной сбор без выпуска: `/sources collect`. По умолчанию это расписание выключено.
После сна сервера пропущенные запуски объединяются в одно актуальное задание.

Пример небольшого начального набора:

```text
/sources on cbr.hd_base.keyrate
/sources on cbr.hd_base.infl
/sources on cbr.hd_base.zcyc_params
/sources on cbr.hd_base.bliquidity
/sources on cbr.hd_base.mrrf.mrrf_7d
/sources on cbr.ruonia.rate
/sources on cbr.ruonia.volume
/sources on cbr.fx.usd
/sources on moex.imoex.close
/market
```

Каталог включает все 29 основных разделов `https://cbr.ru/hd_base/` и вложенные
страницы, обнаруженные при проверке 04.10.2026. Карточки содержат источник,
частоту, единицы, методику, ссылки на оригинальные выгрузки и статус загрузки.
`/sources show ID` открывает карточку. Справочные страницы, документы и разделы
с интерактивными фильтрами доступны как ссылки на оригинал; их отсутствие числовых
наблюдений не считается нулевым значением. Автоматическое прогнозирование
справочников, годовых/квартальных архивов и рядов с неизвестными единицами отключено.
Заголовки числовых HTML-таблиц проверяются по сохранённому контракту; смена схемы
даёт частичный результат с ошибкой, а не подменённые показатели.

Администратор добавляет бумаги командой `/sources moex shares SBER TQBR` или
`/sources moex bonds КОД РЕЖИМ`. После добавления включите соответствующие ID в
каталоге. Режим торгов сохраняется вместе с инструментом, цены облигаций имеют
единицу «% номинала». ISS используется без ключей: доступ и глубина истории зависят
от открытых методов, задержка указана в карточке. Данные разных режимов не суммируются.

Подписчик выбирает собственные ряды через `/indicators ID,ID` или кнопки;
`/indicators all` восстанавливает все включённые показатели. Доступны профили
`/market all`, `/market macro`, `/market investment`, `/market liquidity`.
Наклон кривой, её кривизна и спред RUONIA к ключевой рассчитываются при наличии
соответствующих рядов на одинаковую дату.

### Графики: период и прогноз через кнопки

### Навигация Telegram

`/start` и `/menu` открывают выбор проектов: **Рынок и экономика** и **Жизнь**,
а также состояние и помощь. Отчёты, графики, аналитика, доллар и личные настройки
находятся в карточке рынка. Управление сервисом видно только администратору.
`/settings` открывает личные настройки рынка.
Главное меню больше не добавляется целиком к каждому сообщению.

Переходы и изменения настроек редактируют текущий экран. Выбор отмечен **✓**;
стрелки «Предыдущая/Следующая страница» листают список, а **«Назад»** возвращает
в родительский раздел. Отчёты и файлы приходят отдельно и не переписываются.
После запуска задания остаётся подтверждение и возврат; повтор устаревшей кнопки
запуска не создаёт дополнительное задание. `/cancel`, кнопка **«Отмена»** или
переход в другое меню прекращают ввод без сохранения незавершённого значения.
При ошибке ввода можно исправить значение, не начиная форму заново.
Отмена поиска ЦБ возвращает в каталог; возврат из карточки сохраняет страницу
и поисковый запрос. Выбранная валюта в параметрах архива отмечается галочкой.
Комиссии и риск покупки USD имеют отдельный компактный экран: сохранение,
исправление ошибки и отмена возвращают к этим параметрам. Своя дата возвращает
к выбору срока покупки. Одинаковые активные запросы доллара объединяются;
после завершения можно выполнить новый расчёт. Кнопка проверки выполнения
возвращает к доллару; подписчик видит состояние только собственных заданий.
В расписании графика показано, есть ли ещё не применённые изменения; их сохранение
не включает отправку. Фиксированные даты явно отмечены и не допускаются для
регулярной отправки: сначала выберите скользящий период.

В **Моих настройках** регионы и фразы выбираются кнопками с отметками. Названия
регионов берутся из локального справочника, если он есть; открытие меню не делает
запросов Wordstat. Подписка открывается отдельной карточкой: доставка, время,
часовой пояс, отдельные дни недели и краткий/полный формат. Изменение параметров
не включает доставку автоматически.

В аналитике прогнозы рынка открываются по одному показателю, а пара для корреляции
выбирается в два шага по названиям. Рыночные уведомления имеют карточки с порогом
и вариантами **выключено / сразу / в сводке**. Дополнительные параметры остаются
доступны через команды. В управлении сервисом есть поиск источников, карточки
сведения о них, отдельное расписание общего сбора, глубина первой загрузки,
формы лимитов и фильтры очереди. Отключение пользователя кнопкой требует
подтверждения. Назначение и снятие роли администратора доступны в карточке пользователя;
администраторы из `ADMIN_TELEGRAM_IDS` защищены настройками сервера.

Для организации интерфейса использованы рекомендации
[Telegram об inline-клавиатурах и редактировании сообщений](https://core.telegram.org/bots/features#inline-keyboards)
и [пример интерактивного меню python-telegram-bot](https://docs.python-telegram-bot.org/en/stable/examples.inlinekeyboard2.html).

### Построение графика

Откройте `/chart` или кнопку **«Графики»** в главном меню. Выберите RUONIA,
показатели рынка/ЦБ или Wordstat, затем отдельный показатель либо все свои
показатели. Список показателей имеет страницы. Рынок показывает только источники,
которые включил администратор и которые входят в ваш личный выбор.

Период: месяц (30 дней), 3 месяца (90), 6 месяцев (180), год (365), вся история
или **«Свои даты»**. В последнем случае отправьте, например,
`2025-01-01 2026-10-01`; `/cancel` отменяет ввод. Конец не может быть в будущем.
Готовые периоды отсчитываются от последней загруженной даты выбранных рядов.
Настройки сохраняются отдельно для каждого пользователя и раздела.

Wordstat использует недельную историю из SQLite, а открытие графиков не делает
запросов к Яндексу. Если истории выбранных фраз нет, экран предлагает
**«Загрузить данные из Яндекса»**; после получения отчёта вернитесь к графикам.
При наличии истории показаны последняя дата и кнопка **«Обновить данные из Яндекса»**.
То же действие доступно через `/report wordstat`. Оно использует общий кэш и
дневной бюджет Wordstat; платный AI для него не требуется. Существующие
`WORDSTAT_OAUTH` и `WORDSTAT_CLIENT_ID` сохранены: адаптер обращается к
`https://api.wordstat.yandex.net/v1/dynamics`. Ошибки HTTP 401/403/404/429
показываются с безопасной подсказкой; ответ сервера и токен не включаются в сообщения.

Страница [старого API Wordstat](https://yandex.ru/support2/wordstat/ru/content/api-wordstat)
теперь направляет на [Wordstat в Yandex Search API](https://aistudio.yandex.ru/ru/docs/search-api/concepts/wordstat).
Поддержаны оба интерфейса; по умолчанию остаётся `WORDSTAT_BACKEND=legacy`.
Чтобы подключить новый API, локально добавьте в `.env`:

```dotenv
WORDSTAT_BACKEND=cloud
WORDSTAT_FOLDER_ID=
WORDSTAT_API_KEY=
```

Заполните ID каталога и отдельный API-ключ сервисного аккаунта. По
[документации Яндекса](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-getdynamics),
нужна роль `search-api.webSearch.user`, для ключа — область `yc.search-api.execute`.
Вместо ключа можно задать `WORDSTAT_IAM_TOKEN`, оставив `WORDSTAT_API_KEY` пустым;
одновременно оба секрета не допускаются. Старый `WORDSTAT_OAUTH` для cloud не используется.
Запросы отправляются на `https://searchapi.api.cloud.yandex.net/v2/wordstat/`;
даты, устройства, регионы и ответы переводятся в формат существующего хранилища.
Для этого сервиса действуют [тарифы Яндекса](https://aistudio.yandex.ru/ru/docs/search-api/pricing);
автоматического переключения или платных проверочных запросов при запуске нет.

После изменения `.env` перезапустите `serve` и запросите `/report wordstat`.
SSL/TLS-ошибка завершает сбор без повторов: проверка сертификата всегда включена.
После исчерпания сетевых повторов или общей ошибки авторизации/лимита оставшиеся
фразы и регионы не запрашиваются; сохранённые результаты остаются доступными.
Повторные задания Wordstat и регионов используют сохранённый результат и причину
паузы в течение пяти минут. Смена legacy/cloud создаёт отдельный кэш и снимает
зависимость от ошибок прежнего подключения. TgCrypto — необязательный ускоритель;
его отсутствие не объясняет ошибки TLS и разрывы подключения Telegram.

В настройке **«Прогноз»** доступны недели и месяцы до 24 месяцев, а также ввод
своего срока. Для квартального ряда предел — 8 кварталов, годового — 2 года.
**«Без прогноза»** выключает прогноз. Нажмите **«Построить график»**; история
для обучения модели остаётся полной независимо от периода отображения. Если выбран исторический
период, текущий прогноз скрывается, чтобы не использовать более поздние данные.
При недостаточной истории или устаревшем прогнозе бот сообщает об отсутствии
прогноза. Пропуски не заменяются нулями и не соединяются линией; редкие наблюдения
показаны точками. При выборе всех показателей графики приходят страницами по 12.
Под выпуском есть **«Следующие графики»** и **«Предыдущие графики»**; они сохраняют
исходный выбор и порядок, даже если настройки меню затем изменились. Сначала
показаны свежие ряды с большим охватом, затем редкие и архивные. Ряды без значений
в выбранном периоде перечисляются отдельно и не занимают места на страницах.
Под страницами есть **«☐ Присылать остальные по готовности»**. Галочка включает
отправку оставшихся страниц только этого выпуска. Они готовятся последовательно
из БД и отправляются после подтверждения предыдущей страницы. Снимите галочку,
чтобы остановить очередь и оставшиеся части; при возобновлении подтверждённые
сообщения не дублируются. Режим сохраняется при перезапуске. Неоднозначная доставка
после таймаута блокирует переход дальше до решения администратора.

Кнопки **CSV** и **Excel** экспортируют тот же выбранный показатель и период.
Графики строятся в общей очереди по сохранённым данным, без рассылки другим
пользователям и без внешних API. Для загрузки свежих данных сначала запросите
отчёт соответствующего раздела или администратор может выполнить `/sources collect`.
Обычные `/report` и `/market` сохраняют прежнее представление; выбранный период
применяется к разделу `/chart`.

```text
/correlations add ID_1 ID_2 0 60
/correlations add ID_1 ID_2 1 120
/correlations events ID|пожар|213
/forecasts market
/backtest market 12
/export market xlsx 2025-01-01 2026-10-01
```

Положительный лаг означает, что первый ряд предшествует второму. По умолчанию
сравниваются изменения и доходности; режим `levels` включает исследование уровней.
Месячные значения не размножаются на ежедневные наблюдения. Анализ событий использует
сохранённые региональные сигналы пользователя и требует десять независимых событий.
Корреляция и изменения после события описывают связь, не доказывают причинность.

Прогнозы рассчитываются локально: последнее значение, затухающий тренд и ridge.
Более сложная модель выбирается при улучшении MAE минимум на 5% на последовательной
проверке. Показываются ошибки, базовый метод и диапазон 80%, если для его калибровки
есть десять прошлых ошибок. Нехватка истории/покрытия оставляет ряд без прогноза.
Срок выбирается в настройках графика, максимум — 24 месяца. Для ежедневных рядов
дальний прогноз показывается реже: первые 12 недель, затем месячные точки.
При недостатке десяти проверочных ошибок последнее значение показывается серым
пунктиром как **сценарий без достаточной проверки**, без прогнозного диапазона.
Проверенные горизонты показаны отдельно с доступным диапазоном 80% и MAE.
Календарь учитывает дополнительные выходные 2026 года по опубликованному перечню
ЦБ: <https://cbr.ru/other/holidays/>. Исправление календаря создаёт новую версию
расчёта; ранее сохранённые прогнозы остаются в истории.
Дальний прогноз не учитывает неизвестные будущие решения ЦБ и внешние события.
Для административной ставки доступен личный сценарий `/market scenario ID 1.0`
(изменение в процентных пунктах). Это заданный сценарий, а не предсказание решения ЦБ.
Ключевая ставка и другие административно задаваемые значения в графиках получают
отдельную подпись **«Условие: без изменений (не прогноз)»**. Для этого условия не
публикуются MAE, вероятность или статистический диапазон, даже при длинной истории.
Месячный ряд ключевой ставки не подменяет актуальные дневные данные: подпись указывает
месяц последнего факта. При истории длиннее пяти лет и включённом будущем участке
график дополнен отдельной увеличенной панелью последних двух лет; верхняя панель
сохраняет выбранный период. Диапазоны дат фактов и будущего участка указаны отдельно.

История хранит исправления, дату публикации при её наличии и время получения отдельно.
Выпущенный прогноз сохраняет IDs входных версий и не переписывается после исправлений.
Исторические backtest помечены ретроспективными: доступная сейчас история могла быть
пересмотрена. При неизвестной дате публикации время получения не объявляется её заменой.

Рыночные уведомления принадлежат пользователю, исходные шаблоны выключены:

```text
/alerts market
/alerts market add ID deviation 3
/alerts market set НОМЕР threshold=3 window=60 cooldown=24
/alerts market immediate НОМЕР
/alerts market digest НОМЕР
/alerts market digest 18:30
/alerts market off НОМЕР
```

Типы: `above`, `below`, `change` (проценты), `deviation` (стандартные отклонения),
`cross` (пересечение уровня), `correlation`. Для корреляционного сигнала по умолчанию
нужны коэффициент от 0,6, изменение от 0,2, два подтверждения и поправка на множественные
проверки. Время сводки — Москва; повтор правила ограничен сутками. Существующие
административные `/alerts` для Wordstat продолжают работать отдельно.

Расширенные настройки администратора:
`/sources history daily|weekly|monthly ЛЕТ`,
`/sources features ЦЕЛЕВОЙ_ID ID,ID` (до десяти рядов),
`/sources params ID UniDbQuery.ПАРАМЕТР=ЗНАЧЕНИЕ`,
`/sources unit ID ЕДИНИЦА` (после проверки единиц в оригинале).
Стандартная глубина — 5/10/20 лет. Обновление объединяется на 15 минут для всех
получателей; транспорт ограничивает обращения и повторно использует одинаковые ответы.

## Выдача доступа к боту

В личном чате администратора: `/admin` → «Пользователи» → «Добавить пользователя».
Введите **числовой Telegram ID**, затем попросите пользователя открыть бот и нажать
`/start`. Меню показывает, выполнен ли этот шаг. При выдаче и изменении прав бот отправляет
приветствие, роль и список доступных функций. Если пользователь ещё не обращался к боту,
уведомление ожидает его первого `/start`: Telegram не разрешает боту начинать такой диалог.
Команды `/allow ID`, `/deny ID`, `/users` сохранены; кнопки позволяют отключать и
восстанавливать доступ. Новый пользователь — подписчик, расписания выключены.
Повторное добавление сохраняет настройки. После восстановления расписания необходимо
включить заново; пропущенные задания и сообщения не воспроизводятся автоматически.

Отзыв доступа отменяет ожидающие персональные задания и запрещает последующие части
доставки. Общий сбор продолжается. В карточке пользователя можно назначить администратора
или снять эту роль с подтверждением. Нельзя понизить себя, последнего администратора
или администратора из `ADMIN_TELEGRAM_IDS`. Перед полным отключением сначала снимите роль.
Журнал выдачи/отзыва хранится в `access_audit`, без секретных значений.

## Автономная проверка рыночных функций

```powershell
.\.venv\Scripts\python.exe main.py once --section market --dry-run --no-charts
.\.venv\Scripts\python.exe main.py export --section market --format xlsx --output data/market.xlsx
.\.venv\Scripts\python.exe main.py backtest --section market --output data/market-backtest.json
.\.venv\Scripts\python.exe scripts/benchmark_market.py
```

`scripts/check_market_live.py` отдельно проверяет публичные ЦБ/ISS и сохраняет базу,
графики и экспорт в `.test-tmp/market-live/`; Telegram и платные API не запускает.
`scripts/update_market_catalog.py` вручную обновляет каталог и контракты. Изменения
контрактов нужно просмотреть перед использованием; сервис сам их не переписывает.
Расчёты очереди ограничены четырьмя вычислительными потоками. Замер на Windows не
заменяет измерение на Raspberry Pi; локальная LLM в тест нагрузки не входит.


### Расширенный каталог ЦБ, сравнение рядов и сверка истории

После обновления остановите старый процесс `serve` сочетанием Ctrl+C и запустите:

```powershell
.\.venv\Scripts\python.exe main.py serve
```

При первом открытии базы после обновления схема SQLite переходит на версию 3
транзакционно, с резервной копией рядом с исходной базой. `.env`, пользовательские
файлы и прежние наблюдения сохраняются. Веб-панель остаётся выключенной.

**Один график RUONIA на 1/3/6 месяцев:** `/chart ruonia` → **«RUONIA 1 + 3 + 6 месяцев на одном графике»**
→ период истории → срок прогноза → **«Построить график»**.
Это три опубликованные срочные ставки, рассчитанные по прошлым данным;
срок будущего прогноза задаётся отдельно. В выборе показателей также доступны
поиск, избранное, недавние и сравнение до шести рядов. Галочки обозначают выбор.
Сопоставимые единицы объединяются на одном графике; разные единицы — в отдельных
панелях. Цвет истории совпадает с цветом прогноза. Диапазоны можно отключить.
Настройки личные. Сохранение графика в расписание сохраняет и срок прогноза,
и выбранный набор. Для еженедельной отправки выберите пятницу, время и включите
расписание. Сбор данных и отправка графиков включаются отдельно.

**Все показатели ЦБ в аналитике:** проект «Рынок» → **«Аналитика» →
«Показатели Банка России · все базы» → группа → база**. Каталог виден и до
подключения источников, включая все 29 разделов. Есть поиск по названию,
пагинация, возврат к родительской базе и отметка подключения.
Администратор нажимает **«Подключить и загрузить»**: выбранная база попадает
в общую очередь; бот отдельно сообщит результат и охват. Повторное нажатие
не дублирует незавершённое задание. История других баз при этом не загружается.
После завершения откройте **«Наборы и показатели»**, выберите числовой ряд,
затем график, прогноз, корреляцию, уведомление или CSV/Excel. Личный набор
показателей пополняется выбранным рядом; чужие подписки не меняются.
Расписания и оповещения включаются отдельно.
Кнопка **«Проверить прогноз на истории»** присылает метрики и `backtest.json`;
для изображений используйте **«График и прогноз → Построить график»**.
Пустые ряды не останавливают общий график и не занимают лимит из 12 изображений.
В MIACR ставки обозначены в процентах, обороты — в млн рублей либо млн долларов;
название показывает валюту и группу банков. Исправление этих метаданных при
запуске сохраняет идентификаторы, наблюдения и историю исправлений без скачивания.

Валютная база включает 54 опубликованные валюты с нормализацией номинала;
в архиве редких валют выбор валюты доступен кнопкой в карточке набора.
Внешняя торговля услугами разделяет импорт и экспорт. Даты публикации
RUONIA хранятся отдельно от идентификатора ряда. Справочники, нерегулярные
события, архивы и опубликованные прогнозы ЦБ имеют соответствующие отметки:
их наличие не означает возможность построить обычный прогноз на сегодня.
Ежедневные валютные интервенции за последние два проверенных года содержат
прочерки; месячный ряд доступен. Пропуски сохраняются, нулями не заменяются.

Результат проверки всех разделов и команды повторной проверки —
[docs/cbr_coverage.md](docs/cbr_coverage.md). Автономные тесты проверяют путь
от официальной таблицы до SQLite и аналитики, а также права и повторный сбор.

**Управление источниками:** `/sources` → тематическая группа → набор → показатель.
Все 29 корневых разделов `hd_base` доступны в шести группах: ставки и инфляция,
валюты и металлы, денежная база и резервы, ликвидность, операции ЦБ,
внешний сектор. Вложенные наборы имеют страницы по восемь пунктов, поиск,
карточку источника, состояние сбора, единицы, частоту, ссылку, экспорт и сверку.
Справочные страницы и архивы сохраняются снимками и экспортируются; наличие
страницы в каталоге не означает, что её текст является числовым рядом.
Числовой сбор использует отдельные проверяемые контракты таблиц. Неизвестные
единицы требуют проверки администратором до прогнозирования. Изменение
структуры даёт диагностируемую ошибку, другие наборы продолжают обработку.
Параметры официальной формы можно задать через `/sources params ID ключ=значение`;
смена параметров выключает предыдущие дочерние ряды без удаления истории.

Ежемесячный MIACR разделяет таблицы и валюты. Периоды усреднения резервов
сохраняются как нерегулярные события. Коэффициенты резервирования загружаются
полным снимком один раз. Архив трансграничных переводов 2006–2021 доступен
отдельными квартальными наборами по направлению и показателю; исходный выбор —
«Всего по странам», параметры `CC_КОД=on` добавляют страны официальной формы.
Архивы не выдают прогноз на сегодня. Опубликованный ЦБ прогноз ликвидности
отмечен как официальный прогноз и не используется как фактическое наблюдение.

**Кэш:** обычный сбор ЦБ использует SQLite и запрашивает недостающие диапазоны.
Просмотр, построение графика и экспорт повторно историю не загружают.
Справочники и полные снимки обновляются отдельной сверкой; текущий официальный
прогноз проверяется не чаще одного раза в день. Пустой ответ не превращается в
ноль или подтверждённое удаление данных.

**Сверка:** администратор открывает `/integrity` или карточку источника →
**«Проверить загруженную историю»**. Можно проверить все загруженные наборы либо
показатель и даты. Выполненные диапазоны записываются в контрольные точки;
проверку можно отменить или продолжить после сбоя. Инцидент показывает
значение до/после, методику, важность и подробности. Пересмотр источником
сам по себе не означает взлом. Исправления принимаются или отклоняются
администратором; прежние версии и выпущенные прогнозы сохраняются.
Подтверждённое исчезновение наблюдения сохраняется как пропуск. Повторный
инцидент с теми же значениями не дублируется. Справочные снимки тоже требуют
подтверждения перед заменой принятой версии.

Ежемесячная сверка **выключена**. Её можно включить в боте: 1-го числа в 03:00
по Москве; пропущенные после сна проверки объединяются в одну. Обычные
инциденты приходят сводкой после 18:00, критические — сразу через очередь.
Сводка объединяет записи по базе и типу проблемы: показывает число наблюдений,
показателей и период. Сотни записей не превращаются в сотни строк сообщений;
отдельные значения и решения доступны по кнопке «Открыть журнал целостности».
Повреждение SQLite останавливает исполнителя и записывает локальный аварийный
журнал, даже если основная база недоступна.

Экспорт выбранного графика с явно заданным сроком содержит факты и прогнозные
точки с отдельным типом записи, моделью и границами, если они оценены. XLSX/CSV
экранируют формулы в текстовых полях. Прогноз сохраняет срок, версии входных
наблюдений и метаданные; повторный запрос того же расчёта использует сохранённый
результат. Backtest использует срок из личных настроек графика. Для CLI:

```powershell
.\.venv\Scripts\python.exe main.py backtest --help
.\.venv\Scripts\python.exe scripts/benchmark_market.py --months 24
```

Автономный замер на текущем Windows-ПК: 100 рядов, 50 пар корреляций,
24-месячный срок, 3300 прогнозных точек — 126,2 с, пиковая память процесса
178,7 МБ; максимум четыре вычислительных потока. Это замер Windows-ПК,
не измерение производительности Raspberry Pi. Платные API и Telegram не вызываются.


### Доступ к проектам и разделам

`/allow ID`, `/allow @username` или «Управление сервисом → Пользователи → Добавить пользователя» разрешает вход в бот без администраторских прав. В форме можно ввести `@username` либо числовой Telegram ID. Имя проверяется через Telegram; в правах сохраняется постоянный числовой ID, а в ответе показаны имя, `@username` и ID найденного аккаунта. Если Telegram не смог найти аккаунт, попросите пользователя открыть бот и нажать `/start`, затем повторите ввод или используйте ID из ответа бота. Старые сохранённые имена не используются для выдачи доступа при ошибке поиска. Команда `/deny` также принимает ID или `@username`.

Новый пользователь сначала не имеет подключённых проектов. Откройте его карточку и выберите проект целиком либо **«Отдельные функции»**. Галочка означает право доступа, а не включённую рассылку. Источники поисковых индикаторов остаются скрытыми, пока они выключены в конфигурации.

### Мониторинг и история пользователей и сервера

Откройте **«Управление сервисом → Мониторинг и история»** или `/monitor`.
Доступ есть только у действующих администраторов; команды, кнопки, отдельные
карточки и выгрузка проверяют права при каждом обращении.

**Графики истории** доступны в общем обзоре, на экране сервера и в карточке
пользователя. Период: 24 часа, 7/30 дней или вся сохранённая история. График событий
показывает действия и число активных пользователей за час/день, переходы заданий
в готово/ошибку/отмену, ошибки и предупреждения, среднее и максимальное время
обработки действия. Это время не включает ожидание фонового задания. Архивные
снимки исключены из временных графиков; они остаются в журнале и CSV.
График ресурсов показывает среднее и максимум CPU/памяти процесса, минимум
свободного диска и максимум размера базы с WAL за интервал. Интервалы агрегации:
2/15/60/180 минут соответственно; вся история ресурсов ограничена сохранёнными
90 днями. Разные запуски и пропуски измерений не соединяются; запуски отмечены
пунктиром. Отсутствие событий или измерений не означает доступность сервера.

- **По пользователям**: действия, обращения, загрузки, ошибки, задания, доставка,
  выдача и отзыв прав, изменение `@username`, операции винотеки и финансового учёта.
  В карточке обычного управления пользователем также есть кнопка истории.
  `/monitor ID` и `/monitor @username` открывают нужную карточку.
  «Подробнее №…» показывает текст запроса или ввода, название нажатой кнопки,
  контекст формы, подпись и сведения об отправленном файле, ответ бота и связанные
  задания с их текущим результатом и сохранёнными параметрами. Для входящих файлов
  доступны имя, формат, размер и, если Telegram передал их, размеры изображения
  или длительность. Голосовые сообщения, видео и другие неподдерживаемые типы
  также отмечаются с понятным результатом обработки.
- **Сервер**: запуск, время работы, последний сигнал активности, связь с Telegram,
  очередь и текущие задания, отправки, уведомления о правах, состояния источников,
  память процесса и сервера, CPU процесса, размер базы с WAL и свободное место.
  `/monitor server` открывает этот экран напрямую.
- **Журнал**: 24 часа, 7 дней, 30 дней или весь период; фильтр типа событий либо
  ошибок/предупреждений; страницы по 8 событий. Для пользовательского фильтра
  учитываются как его действия, так и изменения его доступа администратором.
  Фильтр сервера показывает события без пользовательского владельца.
- **CSV**: до 10 000 последних событий выбранного фильтра. В подписи указаны
  количество выгруженных строк и полный размер выборки. Страницы и экспорт
  используют зафиксированную границу времени до нажатия «Обновить журнал».

История хранится в рабочей SQLite, в `monitor_events`, `monitor_runtime` и
`monitor_samples`, и сохраняется после перезапуска. Первая миграция создаёт
резервную копию `*.monitor-backup-*.sqlite3`. Существующие права, задания,
доставки, профиль и операции импортируются как **последние сохранённые состояния**
с исходными датами. Прошлые нажатия, несохранённые ошибки и промежуточные этапы
не восстанавливаются. Дата начала подробного журнала показана в обзоре.

Изменения состояния заданий, доставок, прав, источников и операций пишутся
SQLite-триггерами в той же транзакции: откат операции отменяет и её событие.
Действия интерфейса записывают тип команды/кнопки/формы, исход, длительность и
класс ошибки. Подробности новых запросов сохраняются с даты, указанной в обзоре:
текст до 4 000 символов, подпись к файлу до 2 000, контекст формы до 1 000 и ответ
бота до 2 000. Для длинных значений ставится отметка о сокращении. В CSV эти поля
выведены в отдельные колонки. Для ранее поставленных заданий карточка может
показать сохранённые параметры периода, даты прогноза, цены банка и выбора рядов;
прошлые тексты и кнопки без сохранённых подробностей не восстанавливаются.

Файлы целиком, их Telegram download-токены, OCR-текст чеков и тела ответов провайдеров
не дублируются в журнале. Пароли, именованные API-ключи, распространённые форматы
токенов, фискальные номера, данные авторизации, логины/пароли в URL и параметры
ссылок скрываются. Формы с явно секретным полем скрывают ввод целиком. Параметры
заданий показываются по перечню разрешённых полей, без произвольного содержимого payload.
Публичные имена и времена личных расписаний могут присутствовать в событиях
профиля и расписания, включая значения до и после изменения.

Сигнал активности обновляется отдельной задачей раз в 10 секунд, включая время
длительного расчёта. Если свежего сигнала нет 45 секунд, экран показывает отсутствие
подтверждения активности. Запись запуска хранит PID, имя хоста и состояние связи;
новый запуск под блокировкой исполнителя отмечает незавершённый предыдущий как
прерванный, не выдумывая точное время его окончания. CPU — процент одного ядра
по времени процесса между измерениями; на нескольких ядрах он может превышать 100%.
Ресурсы измеряются раз в минуту, измерения хранятся 90 дней. События и история
запусков автоматически не удаляются. Во время сна или полной остановки компьютера
сам бот не сможет послать сообщение: для такого оповещения нужен внешний наблюдатель.

Отдельно выдаются и отзываются: доллар, каталог ЦБ, графики, отчёты, корреляции, проверка прогнозов, экспорт, личные расписания, уведомления, загрузка и карта Vivino, каталог и план дегустаций, **Винотека · добавление вин, запасы и стоимость** (`wine_cellar`). Например, включение только «Доллар» открывает нужный проект, сохраняя остальные функции закрытыми. Подключение проекта целиком разрешает все его функции; для последующего ограничения используйте отдельные галочки. Ранее выданные права Vivino сохраняются без автоматического подключения новой винотеки существующим подписчикам. Винотека позволяет добавлять вино вручную и по этикетке, вести запасы, списания и стоимость независимо от финансового учёта. Для PDF и фото чеков нужны оба права: `life_finance` и `wine_cellar`. Расписанию графиков нужны права на графики и расписания; рассылке отчётов — на отчёты и расписания.

В списке и карточке видны имя, `@username` (если он есть), числовой ID и статус уведомления. Идентификатором остаётся ID: смена имени или username не меняет права. Профиль обновляется при личном обращении пользователя; кнопка «Обновить имя и @username» запрашивает сведения у Telegram, если они доступны боту. По неизвестному ID имя может появиться только после первого обращения пользователя.

При изменении доступа, функций или роли получатель видит приветствие, точные списки **«Отключено»**, **«Добавлено»** и **«Осталось доступно»** по разделам и функциям. Состояния до и после изменения сохраняются вместе с уведомлением; оно не подменяется более поздними правами во время отправки. Быстрые правки объединяются в одно письмо через 15 секунд после последней; возврат к исходному набору не создаёт повторного письма. Полное отключение доступа и ручная повторная отправка уведомляются сразу. Ошибка Telegram не отменяет выданные права; ограничение FloodWait сохраняется при объединении сообщений. После неоднозначного таймаута автоматического повтора нет, в карточке можно явно повторить уведомление. Неизвестному боту пользователю сообщение придёт при `/start`.

Пользователь видит только подключённые проекты и разделы, выбирает собственные показатели, графики, фильтры, уведомления и расписания внутри них. Кнопки, команды, экспорт, история отчётов, очередь и отправка проверяют доступ повторно. Подключать новый раздел себе или другому пользователю может только администратор. Нативное меню команд обновляется при `/start` и изменении подключений.

Отключение раздела или функции отменяет её ожидающие персональные задания и блокирует следующие части доставки. Связанные расписания и правила уведомлений выключаются. Общий сбор данных продолжает работу. Личные данные и настройки сохраняются; повторное подключение не включает расписания автоматически. `/deny ID` закрывает весь доступ; повторный `/allow ID` сохраняет ранее выданные разделы и функции. Назначенные через бот администраторы сохраняются в БД после перезапуска; исходные администраторы из `ADMIN_TELEGRAM_IDS` остаются защищёнными.

При первом обновлении ранее существовавшие права сохраняются как явный фиксированный список разделов, а не сбрасываются. Список хранится в SQLite отдельно от личных подписок (`user_subscriptions:ID`). Перенос выполняется транзакционно с резервной копией `*.access-backup-*.sqlite3` и не повторяется после перезапуска. Новые пользователи получают пустой список. Администратор может сократить доступ существующих пользователей через их карточки.

Права на функции хранятся отдельно (`user_features:ID`). Миграция профилей и уведомлений создаёт резервную копию `*.users-backup-*.sqlite3`, сохраняет прежние права и не отправляет массовых уведомлений. Изменения функций и ролей записываются в `access_audit`.
